# Telegram-контакты агентств — Python для Windows 11

Собирает опубликованные ссылки для связи из Workspace, Ruward, каталога агентств
Яндекса и CMS Magazine. Посещает карточки, указанные в них официальные сайты и
найденные на этих сайтах ссылки на «Контакты», «О компании», «Партнёрам».
Никаких сообщений в Telegram не отправляет.

## Быстрый запуск

1. Установите **Python 3.11 или новее** с https://www.python.org/downloads/windows/.
   Оставьте включённой установку **Python Launcher** (`py`).
2. Распакуйте архив, например в `C:\AgencyParser` (не запускайте прямо из ZIP).
3. Дважды нажмите `install.bat` и дождитесь установки зависимостей.
4. Дважды нажмите `run_sample.bat`. Это небольшая проверка: **до двух агентств из
   каждого источника**, до четырёх страниц сайта на агентство.
5. Смотрите `results\sample\report.json`, `telegram.txt`, `contacts.csv`, `review.csv`.
6. Для обычного сбора запустите `run_full.bat`. Результаты: `results\full`.

Установка зависимостей требует интернета. Прокси ниже относится к запросам
самого парсера. Полный сбор тоже ограничен: по умолчанию **100 агентств на
источник, 30 страниц каталога, 8 страниц сайтов на агентство и 1000 HTTP-запросов
за запуск**, включая robots и редиректы. Это не обещание полного охвата каталогов.
Для других объёмов скопируйте `config.example.json` в `config.json` и измените
лимиты. После исчерпания бюджета запросов повторите ту же команду — оставшаяся
очередь продолжится. Для нового сбора с увеличенными лимитами обнаружения
используйте новую папку `--data-dir results\larger`: уже обработанные списки
автоматически повторно не разбираются.

## Прокси: HTTP / HTTPS / SOCKS5 с удалённым DNS

Один фиксированный прокси используется **для всех запросов парсера**: каталоги,
карточки, сайты, robots.txt и переходы. Ротации прокси нет. При явном прокси
игнорируется `NO_PROXY`, нет переключения на прямое соединение при ошибке.
Проверка TLS остаётся включённой. Для SOCKS используйте именно `socks5h://`, чтобы
имена для запросов разрешал прокси. Полноценная анонимность зависит от самого
прокси и настроек сети; отдельного обращения к сервису определения IP нет.

Откройте **cmd** в папке программы и выполните (подставьте свои данные):

```bat
set "AGENCY_PROXY=socks5h://USER:PASSWORD@HOST:1080"
.venv\Scripts\python.exe parser.py --sample --require-proxy
.venv\Scripts\python.exe parser.py --require-proxy --exclude old.txt
```

Варианты URL: `http://USER:PASSWORD@HOST:8080`, `https://HOST:8443`,
`socks5h://HOST:1080`. Без авторизации уберите `USER:PASSWORD@`.
Спецсимволы в логине/пароле (`@`, `:`, `/`, `#`, `%`) должны быть URL-кодированы.
Для ввода чувствительного URL без записи в историю команд можно использовать
**PowerShell**:

```powershell
$p = Read-Host 'Proxy URL' -AsSecureString
$env:AGENCY_PROXY = [System.Net.NetworkCredential]::new('', $p).Password
.\.venv\Scripts\python.exe parser.py --sample --require-proxy
Remove-Item Env:AGENCY_PROXY
```

Либо укажите строку URL в поле `proxy` вашего `config.json`. Переменная
`AGENCY_PROXY` имеет приоритет. `require_proxy: true` запрещает начало сетевой
работы без явно заданного прокси. Пароли прокси в отчёт и журнал не пишутся;
не передавайте другим свой `config.json` или историю команд.
Если прокси не указан, используются стандартные настройки окружения requests
(в том числе HTTP_PROXY/HTTPS_PROXY), а при их отсутствии — прямой доступ.

## Исключить прежние контакты и продолжить после остановки

Положите прежний TXT, например `old.txt`, в папку программы:

```bat
.venv\Scripts\python.exe parser.py --exclude old.txt
```

По одному адресу `https://t.me/username` в строке, UTF-8; также распознаются
`@username`, голый username и `telegram.me`. Регистр и варианты URL
нормализуются. Старые контакты исключаются из всех трёх выгрузок.
Файл старых контактов не изменяется. Повторяйте `--exclude` при каждом запуске.
Не используйте генерируемый `telegram.txt` этой же папки как файл исключений:
это удалит ранее найденные контакты из текущей выгрузки.

**Ctrl+C** корректно сохраняет результат; следующий запуск с той же папкой
продолжит очередь. Прогресс фиксируется после каждой обработанной страницы.
После выключения питания SQLite восстанавливает последнюю транзакцию; если
остался `.run.lock`, убедитесь, что процесс действительно завершён, затем
удалите только этот файл. Одновременная работа двух процессов с одной папкой
запрещена. Не удаляйте `progress.sqlite3`, `-wal`, `-shm`, пока процесс работает.

По умолчанию ошибки страниц не повторяются. `--retry-errors` возвращает их в
очередь, но **не снимает остановку доменов**, получивших блокировку, CAPTCHA,
авторизацию, 429/503 или сетевую ошибку. Это защищает от повторных запросов при
неисправном прокси. Блокировки сохраняются в SQLite и видны в `report.json`.
Парсер не меняет IP/прокси для их обхода. Повторные запуски работают с оставшимися
доступными страницами. Не пытайтесь продолжать запросы вопреки ограничению сайта.

## Что находится в результатах

- `telegram.txt` — уникальные `https://t.me/username`, по одному на строку.
- `contacts.csv` — `company;telegram;source_page`: связь контакта с компанией и
  конкретной страницей, где он опубликован. На каждый Telegram — ровно одна
  строка, даже если он найден на разных сайтах или у разных компаний.
- `review.csv` — компания, опубликованная ссылка, страница, причина и контекст:
  неясное назначение, приглашения, необычные URL и противоречивые подписи.
  Каждая ссылка записывается один раз. Контакты из `contacts.csv` здесь не повторяются.
- `progress.sqlite3` — сохранённые задачи и находки; источник повторной выгрузки.
- `requests.jsonl` — журнал реальных запросов, HTTP-коды и пропуски по robots.
- `report.json` — лимиты, ход обработки каждого источника, ошибки и остановки.

CSV используют **точку с запятой и UTF-8 с BOM** для Excel Windows.
Дубли определяются после нормализации регистра username и вариантов адреса
(`t.me`, `telegram.me`, `tg://resolve`), без учёта завершающего слеша и обычных
параметров ссылки. Для CSV сохраняется одна из страниц происхождения;
полные находки остаются в базе прогресса. При повторном запуске выгрузки
перезаписываются из базы с той же проверкой уникальности, а не дополняются дублями.
В потенциально опасные для Excel текстовые ячейки добавляется апостроф.
Если Excel не разделил столбцы, импортируйте через «Данные → Из текста/CSV»
с разделителем `;` и кодировкой UTF-8.

Обычная и тестовая выборки имеют разные папки. Можно ограничить источники:

```bat
.venv\Scripts\python.exe parser.py --sources workspace ruward --data-dir results\selected
.venv\Scripts\python.exe parser.py --export-only --exclude old.txt
.venv\Scripts\python.exe parser.py --sample --export-only
```

`--export-only` обновляет выгрузки из SQLite без запросов. Выгрузки относятся
ко всей выбранной базе прогресса; `--sources` ограничивает сетевую очередь.

## Правила отбора и границы

Только адреса, **действительно опубликованные в HTML**: ссылки, их явные атрибуты,
а также видимые полные Telegram URL. Из названия компании и обычных @упоминаний
username не строится. Для Workspace читается опубликованный адрес назначения
трекера — сам запрещённый robots редиректор не вызывается.

Явные локальные «Написать», «Связаться», «Обсудить» позволяют принять контакт.
Просто иконка «Telegram», даже на странице «Контакты», отправляется на проверку.
Подписи «канал», «подписаться», «новости», «блог», ссылки на посты, Share и боты
отбрасываются. При конфликте одного URL с явной подписью канала/бота контакт
переносится в review. Telegram API и проверка существования аккаунтов не
используются: назначение определяется консервативно по опубликованной ссылке и
её ближайшей подписи. Изменение/передача аккаунта после публикации не выявляется.
Содержимое `review.csv` не добавляется в `telegram.txt` автоматически.

Учитываются robots.txt (включая wildcard, Crawl-delay и Request-rate), а также
HTTP 401/403/407/423/429/451/503 и видимые страницы CAPTCHA/авторизации.
При 429 запросы на домен прекращаются, Retry-After фиксируется в журнале.
Нет обхода CAPTCHA, входа в аккаунты, stealth-браузера или отключения TLS.
Если robots недоступен или вместо него приходит HTML, страницы сайта не запрашиваются.
Стандартный переход robots с HTTP на HTTPS / www разрешён для того же имени.

HTML разбирается без исполнения JavaScript; используются также публичные данные,
встроенные в страницу. CMS Magazine догружается через публичный API своего
каталога. Сайты с контентом только после выполнения JavaScript могут потребовать
ручной проверки. Повреждённая/изменившаяся разметка может дать нулевой результат —
смотрите ошибки `no_official_website_found` / `no_agencies_or_navigation_found`
в отчёте. Ноль контактов сам по себе не доказывает отсутствие контактов.

## Проверка кода

```bat
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Результат небольшой реальной проверки и её ограничения — в `SAMPLE_REPORT_RU.md`.
Файлы из `checked_sample` — сохранённый пример проверки, они не используются как
текущий прогресс или список исключений.
